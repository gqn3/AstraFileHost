# Installation

[English](INSTALLATION.md) | [العربية](ar/INSTALLATION.md) · [Project overview](../README.md)

## Requirements

- Node.js 22.12 or newer, npm and Git. The lockfile is authoritative; use `npm ci`.
- Docker Engine/Desktop with Compose v2, running in Linux container mode.
- At least 40 GiB free is a useful starting point for this reference installation. Admission preserves a configurable floor (15 GiB by default); add space for files, multipart staging, database growth and backups.
- Available loopback ports: 18400 (web), 18402 (API), 18432 (PostgreSQL), 18479 (Redis), 18401 (S3), 18403 (storage metrics).

## Fresh local installation

Run from PowerShell or a POSIX shell:

```sh
git clone https://github.com/gqn3/AstraFileHost.git
cd AstraFileHost
npm ci
npm run setup:local
docker compose --env-file .env -f infra/compose/local.yml up -d --build --wait
npm run migrate
npm run storage:init
npm run dev
```

Access to the private GitHub repository is required. Keep the directory named `AstraFileHost`: the setup script checks its scope. It creates `.env`, `.secrets/` and `.local/`, generates independent random secrets and refuses to overwrite `.env`. Do not copy `.env.example` before this command.

Open `http://localhost:18400/setup`. Read `.secrets/bootstrap-token` locally and enter it in the setup form with your chosen owner credentials. Do not paste the token into a ticket or publish it. The API stores its hash and permits a single owner bootstrap. Registering subsequent accounts requires administrator activation by Account ID.

The `dev` command starts the API, Vite and worker. Check `http://localhost:18400/health/ready`; a reachable frontend alone does not prove dependencies or the worker are healthy.

## Existing installation

Keep existing secrets and volumes. Run `npm ci`, start the same Compose project, apply required migrations after an appropriate backup, then start the application. Do not rerun fresh provisioning or replace key rings. Stop development with Ctrl+C; stop only these containers with:

```sh
docker compose --env-file .env -f infra/compose/local.yml stop
```

This preserves volumes. Removing volumes destroys their contents.

## Manual configuration and external services

As an alternative to `setup:local`, copy `.env.example` to `.env` using your shell and configure every required value from [Configuration](CONFIGURATION.md). Generate all keys independently; `node scripts/setup-privacy-keys.mjs .env` adds only missing privacy key rings. It does not create the database, Redis/S3 credentials, cookie secret or bootstrap token/hash. Start your configured dependencies before `npm run migrate` and `npm run storage:init`.

The local Compose file expects the secret files generated by `setup:local`. A manual external-service installation does not need that Compose stack. Browser access, exact CORS and public storage endpoints still need validation. Production is a separate [Linux deployment procedure](DEPLOYMENT.md).
